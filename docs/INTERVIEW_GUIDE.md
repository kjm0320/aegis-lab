# 면접 준비와 2분 시연 대본

이 문서는 준비용입니다. 실제로 이해하고 수행한 범위를 기준으로 설명을 조정하세요.

## 2분 시연 순서

| 시간 | 보여줄 화면 | 설명할 내용 |
|---|---|---|
| 0:00-0:20 | 프로젝트 사례 | 목적은 허가된 진단 결과의 정리와 개선 관리. 현재 버전은 규칙 기반이며 AI 도움으로 구현함 |
| 0:20-0:45 | 접근 제어 사례 | 합성 사용자 alice가 다른 소유자의 주문을 읽는 현상, 소유권 검증 후 403 전환, 정상 조회 유지 |
| 0:45-1:05 | SQL·쿠키 사례 | 매개변수화로 비공개 레코드 미노출, 쿠키 속성 검사. 실제 브라우저 강제 동작은 미검증 |
| 1:05-1:35 | 수정 전 결과 가져오기 | 75점의 계산 근거, 문제 필터, 증거와 개선안, 재검증 기록 후 해결 처리 |
| 1:35-2:00 | 수정 후·자료 | 100점은 입력 3건에 한정. 실행 증거·테스트와 코드 경로, 자신의 실제 기여와 남은 과제 설명 |

현재 제공물은 대본입니다. 실제 브라우저 화면을 녹화한 시연 영상이 아닙니다.

## 예상 질문과 확인 포인트

1. **왜 75점인가요?** high 2건의 20점과 medium 1건의 5점을 100점에서 뺐습니다. 자체 지표이며 CVSS가 아닙니다.
2. **100점이면 안전한가요?** 등록된 3건의 감점이 없다는 의미입니다. 전체 공격 표면이나 미점검 범위를 보증하지 않습니다.
3. **AI는 어디에 사용했나요?** 개발 지원에 사용했습니다. 런타임 분석은 규칙 기반이며 LLM을 호출하지 않습니다.
4. **인증과 인가는 어떻게 구분했나요?** 실습은 인증 완료 주체를 fixture로 주입하고, 리소스 소유권 검증의 유무를 비교합니다. 인증 체계 자체는 구현·평가 범위에서 제외했습니다.
5. **SQL 인젝션은 어떻게 막았나요?** 사용자 문자열을 SQL 문장에 결합하지 않고 바인딩 매개변수로 전달했습니다. 정상 검색과 특수 문자 입력도 회귀 검증합니다.
6. **쿠키 속성만으로 세션 보안이 완성되나요?** 아닙니다. 만료·재발급·세션 무효화·TLS·CSRF 방어 등은 추가 검토 대상입니다. 이 사례는 응답 속성 검증에 한정됩니다.
7. **45개 테스트가 실제 브라우저 테스트인가요?** Node 모델·이벤트 어댑터 테스트와 Python 프로세스 내부 실습입니다. 실제 브라우저 렌더링이나 인증 경로 검증은 별도입니다.
8. **입력에 스크립트가 들어오면 어떻게 하나요?** 문자열을 이스케이프하거나 textContent로 표시합니다. 렌더링 함수와 회귀 테스트를 함께 보여 주세요.
9. **직접 한 부분은 무엇인가요?** CONTRIBUTIONS.md의 실제 수행 범위와 이후 직접 남긴 커밋·실습 기록만 설명하세요.

## 첫 독립 실습

코드를 실행해 보고 LAB-001의 `order['owner'] != actor` 조건이 빠지면 어떤 테스트가 실패하는지 확인하세요. 수정 모드에서 이 조건을 지운 실험은 로컬에서만 수행하고, 다시 복원한 뒤 테스트가 통과하는지 기록하세요. 그 수정 이유를 자신의 말로 3문장으로 정리하면 첫 학습 기록이 됩니다.
